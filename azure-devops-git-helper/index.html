About Git Helper for Azure DevOps

Git Helper is a Chrome Extension (Manifest V3) that reads the commits on an Azure DevOps Pull Request and generates a clean, structured PR description from them. It works on dev.azure.com and *.visualstudio.com and re-mounts automatically as you navigate between PRs in Azure DevOps's single-page application.

Commit-driven

Reads commits directly from the Azure DevOps REST API — no copy-paste required.

Noise filtering

Automatically excludes merge commits and low-value messages like wip, fix typo, and rebase.

Conventional Commits

Recognises feat, fix, refactor, perf, test, and more — converts them into readable sentences.

AI refinement (Pro)

Optionally refines the generated draft using OpenAI, Anthropic, or Azure OpenAI — requires a license key.

Installation

Step 1 — Install from the Chrome Web Store

Add to Chrome — it's free

Click Add to Chrome on the store page, then confirm by clicking Add extension in the dialog. The Git Helper icon will appear in your toolbar immediately — no restart required.

Step 2 — Pin the extension (recommended)

Click the puzzle-piece icon (Extensions) in the Chrome toolbar, find Git Helper for Azure DevOps, and click the pin icon to keep it visible in the toolbar.

Step 3 — Configure (optional)

Click the toolbar icon to open the settings popup. All settings are optional unless noted:

SettingWhen you need it
PAT tokenPrivate repositories — needs Code (Read) scope. Public repos work without it.
License keyRequired to unlock AI description refinement (Pro feature).
AI provider & API keyShown after entering a valid license key. Bring your own key from OpenAI, Anthropic, or Azure OpenAI.

Step 4 — Generate a PR description

  1. Open any Pull Request on dev.azure.com or *.visualstudio.com
  2. Click the PR Description button that appears in the bottom-right corner of the page
  3. A panel opens and fetches the commits for the PR
  4. Review the commit checklist — uncheck anything you want to exclude
  5. Click Generate Description
  6. Edit the output in the text area, then click Copy
  7. Paste the description into the Azure DevOps PR description field

Updating the extension

Chrome updates extensions from the Web Store automatically. To force an immediate update, go to chrome://extensions and click Update in the top-left corner.

Removing the extension

Go to chrome://extensions, find Git Helper for Azure DevOps, and click Remove. All locally stored settings (PAT token, license key, API key) are deleted along with the extension.

Permissions Requested and Why

Git Helper requests only the minimum permissions required to provide its functionality. The following table explains each permission, the feature that requires it, and why a narrower permission would not be viable.

Permission User-facing feature Why narrower is not viable
storage Saves the user's settings (PAT token, toggles, license key, AI provider and API key) to chrome.storage.local so they persist across browser sessions and do not need to be re-entered. Without this permission, settings reset every time the extension is loaded. There is no narrower scope for local, per-extension storage.
host_permissions:
dev.azure.com/*
*.visualstudio.com/*		 Injects the content script into Azure DevOps PR pages and calls the Azure DevOps REST API (/pullRequests/{id}/commits) to fetch the commit list for the open PR. Content scripts can only be injected into pages that match their declared host permissions. Without these permissions, the extension cannot read the page URL, inject the PR Description button, or call the Azure DevOps API from within the page context. Narrower patterns (e.g. only */pullrequest/*) are not supported by Chrome's host permission syntax for content scripts.
host_permissions:
api.openai.com/*
api.anthropic.com/*
*.openai.azure.com/*		 Sends the generated draft description to the user's chosen AI provider for refinement — only when the AI feature is enabled, a license key is present, and the user clicks Generate. The AI provider is selected and configured by the user in the settings popup. Chrome extensions cannot call cross-origin URLs from content scripts unless those origins are declared in host_permissions. These three entries cover OpenAI, Anthropic, and Azure OpenAI. Only the provider the user selects is ever contacted. If AI is disabled, none of these permissions are exercised.
No background permissions Git Helper does not use tabs, history, cookies, webRequest, bookmarks, identity, or any other sensitive Chrome API. It has no access to pages outside of Azure DevOps.

Privacy Policy

Last updated: September 27, 2026

Overview

Git Helper for Azure DevOps is a Chrome Extension that generates PR descriptions from commit messages on Azure DevOps Pull Request pages. This policy explains what data the extension accesses, how it is used, and what leaves your browser.

Data Stored Locally

The following values are saved to chrome.storage.local — stored exclusively in your browser on your device, never transmitted to any server operated by this extension:

  • Personal Access Token (PAT) — used to authenticate calls to the Azure DevOps REST API for private repositories. Never sent anywhere other than dev.azure.com or *.visualstudio.com.
  • License key — validated locally in the extension to gate the AI feature. Never transmitted to any server.
  • AI API key — your key for the AI provider you select (OpenAI, Anthropic, or Azure OpenAI). Never sent anywhere other than the selected provider's API endpoint.
  • Settings (include merge commits, group by category, AI provider, AI model, Azure endpoint) — preferences stored locally only.

None of this data is sent to any server operated by the developer of this extension.

Data Sent to Azure DevOps

When you open the PR Description panel, the extension calls the Azure DevOps REST API to retrieve the list of commits for the open Pull Request. This call is made directly from your browser to Azure DevOps using the same session cookies your browser already holds (or your configured PAT token). No intermediate server is involved.

Data Sent to AI Providers (Pro feature only)

When the AI feature is enabled and you click Generate Description, the extension sends the following to your configured AI provider (OpenAI, Anthropic, or Azure OpenAI):

  • The selected commit messages
  • The PR title, source branch name, and target branch name (scraped from the Azure DevOps page)
  • The template-generated draft description

No source code, file diffs, PAT tokens, API keys, personal account information, or any other data are included in the AI request. The AI provider you choose processes this data according to their own privacy policy and terms of service.

When the AI feature is disabled (or no license key is entered), no data is sent to any AI provider — all processing happens locally in your browser.

Data Not Collected

Git Helper does not collect, transmit, or store:

  • Usage analytics or telemetry
  • Browsing history
  • Identifiers, email addresses, or account information
  • Source code, file contents, or repository metadata
  • Any data from pages other than Azure DevOps PR pages

Third-Party Services

The only third-party services the extension may contact are:

  • Azure DevOps REST API (dev.azure.com / *.visualstudio.com) — to fetch commits for the open PR.
  • Your chosen AI provider (api.openai.com, api.anthropic.com, or *.openai.azure.com) — only when AI is enabled and you click Generate.

No analytics, advertising, tracking, or data-broker services are used.

Data Retention and Deletion

All data stored by Git Helper lives in chrome.storage.local on your device. You can delete it at any time by:

  • Clearing the extension's storage via chrome://extensions → Git Helper → Clear storage
  • Removing the extension from Chrome

No data associated with you is retained by the developer after the extension is removed.
