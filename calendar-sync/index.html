About Calendar Sync

Calendar Sync is a Google Workspace™ Add-on that helps users who work across multiple Google Accounts™ keep their availability consistent. It reads events from secondary calendars and creates private "Busy [domain]" blocks on your primary calendar automatically — without copying titles, descriptions, attendees, or any other event details.

Privacy-preserving

Only the time slot is copied. Titles, descriptions, locations, and attendees are never shared.

Automatic sync

An hourly trigger keeps calendars in sync with no manual action required.

Up to 2 source calendars

Connect your work, personal, and client calendars — up to 2 source calendars.

Incremental sync

Uses Google Calendar™ sync tokens so only changed events are processed each run.

Setup Guide

What you need

  • A Google Account™
  • Google Calendar™ open in a browser
  • The Calendar Sync add-on installed

Step 1 — Install the add-on

Open the Google Workspace™ Marketplace and search for Calendar Sync. Click Install and follow the prompts. Grant the requested permissions when asked. Open Google Calendar™ — a Calendar Sync panel appears in the right sidebar.

Step 2 — Share your secondary calendars with your primary account

Before Calendar Sync can read a secondary calendar, that calendar must be shared with your primary Google Account™. Do this for each secondary calendar you want to sync:

  1. Sign in to Google Calendar™ with the secondary account (e.g. you@gmail.com)
  2. In the left sidebar, find the calendar → click the three-dot menu (⋮) → Settings and sharing
  3. Under Share with specific people or groups, click + Add people and groups
  4. Enter your primary account email (e.g. you@work.com)
  5. Set the permission to See all event details
  6. Click Send
  7. Switch back to your primary account and accept the sharing invitation if prompted

Repeat for every additional secondary calendar before proceeding.

Step 3 — Add your calendars

In the Calendar Sync panel, click Settings. Calendar 1 is your primary calendar — enter your main Google Account™ email (e.g. you@work.com). Add your secondary calendars below (e.g. you@gmail.com, you@client.com). You can add up to 2 source calendars.

Step 4 — Set your sync window

The sync window controls how far back and forward to create busy blocks.

  • Days in the past — how many days back to mirror (default: 7)
  • Days in the future — how many days ahead to mirror (default: 7)

Step 5 — Save and start

Click Save & Start Sync. The add-on will run a full sync immediately, create "Busy [domain]" blocks on your primary calendar, and set up an hourly trigger to keep everything in sync automatically.

Permissions Requested and Why

Calendar Sync requests only the minimum permissions required to provide its synchronization functionality. The following table explains each OAuth scope, the specific user-facing feature that requires it, and why a narrower scope would not be viable.

Scope User-facing feature Why narrower is not viable
userinfo.email Pre-fills the Calendar 1 field in the setup form with the signed-in account's email address (Session.getActiveUser().getEmail()). This prevents the user from accidentally entering a different account's email as their primary calendar, which would cause mirror events to be written to the wrong calendar. Without this scope, Calendar 1 would be a blank text field. The user could type any email address, including one they do not own. Pre-filling with the verified OAuth identity ensures Calendar 1 is always the account the user authenticated as. No narrower scope provides the authenticated user's email address.
calendar.calendarlist.readonly Validates that each source calendar the user enters in the setup form is already shared with their primary account before attempting sync. If the calendar is not in the user's calendar list, an error is shown immediately with instructions to share the calendar first. The calendar.events scope only permits reading event data and does not return calendar metadata (access role, display name) needed for validation. Without early validation, setup errors would only surface during the first sync run, hours later, with a less helpful error message.
calendar.events Reads events from source calendars to determine busy periods, and creates, updates, and deletes "Busy [domain]" mirror events on the primary calendar. This is the core sync functionality. Write operations — the add-on creates, updates, and deletes mirror events on the primary calendar (Events.insert, Events.update, Events.remove). Neither calendar.events.readonly nor calendar.events.freebusy permits writes.

Read fields not available under calendar.events.freebusy:
  • event.id — keys each mirror to its source event
  • event.extendedProperties — identifies which events are mirrors created by Calendar Sync
  • event.recurrence — copies recurrence rules so one series produces one mirror
  • event.recurringEventId — distinguishes instances from master events
  • event.status = "cancelled" — detects deleted events so mirrors can be removed
  • syncToken — enables incremental sync; not supported under calendar.events.freebusy
calendar.addons.execute Required by Google for all Google Workspace Add-ons to execute card action callbacks (Save, Pause, Resume, Resync, Stop & Clean Up). Without it, none of the add-on's UI buttons would function. This scope is mandated by Google's Workspace Add-on platform. There is no narrower alternative.
script.scriptapp Creates and manages the hourly time-based trigger that automatically keeps calendars in sync without manual intervention. Also used to schedule the one-shot background trigger that runs sync operations after the user saves settings. No narrower scope exists for creating Apps Script triggers. Without it, the add-on cannot run automatically — the user would need to manually trigger every sync, which is not the intended user experience.

Privacy Policy

Last updated: September 26, 2026

Overview

Calendar Sync is a free Google Workspace™ Add-on that helps users synchronize busy time across multiple Google Calendar™ accounts. The add-on creates generic "Busy" calendar blocks so that availability from one configured calendar can be reflected in another calendar without copying the details of the original event.

Limited Use Compliance Statement
The use of raw or derived user data received from Google Workspace APIs (including Google Calendar™ APIs) by Calendar Sync will adhere to the Google API Services User Data Policy, including the Limited Use requirements. User data is used solely to provide the calendar synchronization feature requested by the user and for no other purpose.

Data Accessed

Calendar Sync accesses only the Google user data required to provide its synchronization functionality:

  • Google Account™ email address — to identify the primary calendar account and pre-fill it in the setup form.
  • Calendar list metadata (calendar name and access role) — to validate that source calendars entered by the user are shared with the primary account before attempting sync.
  • Calendar event timing data (start times, end times, status, recurrence rules, sync tokens) from source calendars — to determine when the user is busy.
  • Extended property metadata on mirror events the add-on creates — to identify and track which events belong to Calendar Sync for deduplication and cleanup.

Calendar Sync does not access, use, or store the titles, descriptions, attendee information, conference details, or locations of existing calendar events. Event content is never read or transmitted — only timing information is processed.

How User Data Is Used

User data obtained from Google APIs is used solely to provide the calendar synchronization functionality requested by the user:

  • Email address: used only to identify the primary calendar, not stored separately.
  • Calendar metadata: used only at the moment of setup to validate calendar access; not stored.
  • Event timing data: used only to compute busy periods and create corresponding "Busy [domain]" blocks on the primary calendar.

User data is not used for advertising, profiling, marketing, analytics, AI/ML model training, or any purpose unrelated to calendar synchronization.

Data Sharing and Transfer

  • Calendar Sync does not sell Google user data.
  • Calendar Sync does not share Google user data with advertisers, data brokers, analytics providers, or any third parties.
  • Calendar Sync does not transfer Google Calendar™ data to any external server, database, or third-party service. All processing occurs within Google's own infrastructure (Google Apps Script™).
  • No human (including the developer) has access to users' Google Calendar™ data through Calendar Sync.

AI and Machine Learning

Calendar Sync does not use artificial intelligence or machine learning systems of any kind. User data obtained from Google Workspace APIs is not used to develop, improve, or train any AI or machine learning model — whether operated by the developer or by any third party. No user data is transferred to any AI or machine learning service.

Data Storage and Security

Calendar Sync does not operate an external application server or database. The only data stored by the add-on is the user's own configuration (calendar email addresses, sync window settings, and sync state tokens), which is stored exclusively in Google Apps Script™ User Properties — a per-user, per-script storage mechanism provided by Google that is not accessible to other scripts or third parties.

Calendar event data is processed transiently within Google's Apps Script™ runtime. No calendar content is written to or cached in any external storage controlled by the developer.

Access to Google Calendar™ data is protected by Google's OAuth 2.0 authorization system. Users explicitly grant and can revoke permissions at any time via their Google Account™ security settings. The add-on requests only the minimum OAuth scopes necessary to function (see the Permissions section).

Data Retention and Deletion

Configuration data stored by Calendar Sync is retained only as long as the user keeps the add-on installed and configured.

  • Users can remove all "Busy" calendar blocks created by Calendar Sync by opening the add-on and selecting Stop & Clean Up.
  • Users can reset their configuration by using the Reconfigure option in the add-on.
  • Users can delete all stored configuration data and revoke Calendar Sync's access to their Google Account™ at any time via Google Account™ → Security → Third-party apps with account access.
  • No data associated with a user is retained by the developer after the user revokes access.

Third-Party Services

Calendar Sync does not use any third-party analytics, advertising, tracking, telemetry, or data-processing services. The add-on operates exclusively within Google's infrastructure using Google Workspace™, Google Calendar™ APIs, and Google Apps Script™.

Google API Services User Data Policy

Calendar Sync's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is used only to provide the user-facing calendar synchronization functionality of Calendar Sync.
